# 끝말잇기 — AI + 온라인 2인 + 랭킹

## 데이터
서버가 시작할 때 `data/`에서 직접 읽는 파일:
- `word.txt`: 전체 단어 목록 (548,575개)
- `attack.txt`: 공격 단어 및 깊이 (4,098개 단어)
- `끄글_주요 루트 단어_*.txt`: AI 루트 단어
- `끄글_희귀 루트 단어_*.txt`: AI 희귀 루트 단어
- `끄글_방어 단어_*.txt`: AI 방어 단어
- `끄글_돌림 단어_*.txt`: AI 돌림 단어

`끄글_음절 목록_*.txt`, `끄글_필수 공격 단어_*.txt`는 단어 목록을 분석·생성할 때 쓰는 참고 자료이며 서버 런타임에서는 읽지 않습니다.

## Windows 실행
1. Node.js LTS를 설치합니다.
2. 이 폴더에서 명령 프롬프트/PowerShell을 엽니다.
3. `npm install`
4. `npm start`
5. 브라우저에서 `http://localhost:3000` 접속

## Neon PostgreSQL 연결
서버는 기존 `pg` 드라이버로 Neon PostgreSQL에 연결합니다. 별도 Neon Functions나 Data API를 사용하지 않습니다.

1. [Neon Console](https://console.neon.tech/)에서 프로젝트의 **Connect**를 눌러 브랜치, 데이터베이스, 역할을 선택하고 **pooled connection string**을 복사합니다. URL에는 보통 `-pooler`가 포함됩니다.
2. 실행 환경의 비밀 환경 변수에 `DATABASE_URL`을 설정합니다. 연결 문자열은 소스 코드나 GitHub에 커밋하지 마세요.
3. 서버가 시작될 때 `players`, `kv_store`, `economy_ledger` 테이블을 자동 생성/보완합니다.
4. 배포 후 `/api/health`의 `db` 값이 `"postgres"`인지 확인합니다.

### 로컬 개발
Neon CLI로 연결된 브랜치의 데이터베이스 URL을 로컬 `.env.local`로 가져올 수 있습니다. 이 저장소는 `.env.local`을 Git에서 제외합니다.

```bash
npx neon env pull --env DATABASE_URL --file .env.local
npm run dev:neon
```

또는 `.env.local`의 `DATABASE_URL`을 Neon pooled connection string으로 직접 설정하고 `npm start`를 실행해도 됩니다. Neon의 **direct** 연결을 써야 하는 경우가 아니라면 애플리케이션 트래픽에는 pooled URL을 권장합니다.

## 우리말샘 단어 뜻 조회
단어 클릭 시 공식 [우리말샘 Open API](https://opendict.korean.go.kr/service/openApiInfo)를 통해 뜻풀이를 조회합니다. API 키를 발급받아 서버 비밀 환경 변수 `OPENDICT_API_KEY`에 설정하세요. 키는 브라우저에 전달되지 않으며, 정의가 있는 조회는 서버 메모리에 최대 6시간, 빈 결과는 10분 동안 캐시됩니다. 동시 요청은 같은 API 조회를 공유하고, 캐시는 최대 500개를 최근 사용 순으로 유지합니다. 쿼터 보호를 위해 IP당 분당 60회로 요청을 제한하며, 초과 시 `429`와 `Retry-After`를 반환합니다. 우리말샘에 항목이 없는 단어는 직접 검색 링크를 표시합니다.

- 로컬: `.env.local`에 `OPENDICT_API_KEY=발급받은키`를 설정한 뒤 `npm run dev:neon` 실행
- Render: 웹 서비스의 Environment에 `OPENDICT_API_KEY`를 비밀 변수로 추가하고 재배포
- 키 발급과 사용량 제한은 우리말샘 API 안내를 확인하세요.

## 관전 모드
- 방 목록의 **관전** 버튼, 친구 목록의 **관전** 버튼, 또는 `room:spectate`로 입장합니다.
- 관전자는 플레이어 정원과 별개로 **방당 최대 30명**까지 들어갈 수 있고, 방 화면에 관전자 수가 표시됩니다.
- 관전자는 플레이어 채팅에 쓸 수 없고 **관전 전용 채팅**을 사용합니다. 플레이어와 관전자의 대화가 섞이지 않습니다.
- 관전자는 게임 입력·재시작·추방 권한이 없으며, 마지막 플레이어가 나가면 방과 함께 정리됩니다.
- 랭크/대회 방도 관전할 수 있지만, 관전자에게는 플레이어와 동일한 공개 상태만 전달됩니다.

## 시즌 소프트 리셋·배치고사
- 시즌은 KST 매월 1일에 전환됩니다. 랭크를 치른 모든 계정은 종료 시 레이팅이 `1000 + (현재-1000) × 0.5`로 이월됩니다(시즌 미참가자 포함 — 휴면 계정의 옛 레이팅으로 복귀하는 것을 막습니다).
- 이월된 플레이어는 다음 시즌 **배치고사 5판**을 치릅니다. 배치 중에는 레이팅 변동 폭이 1.5배이며, 승/패 모두 1판씩 소모합니다.
- 대회 우승은 상대 수와 무관하게 배치 1판으로 계산합니다.
- 배치 진행 상황은 랭크 탭과 계정 탭에 표시됩니다. `lastResetSeason` 마커로 같은 시즌에 두 번 리셋되지 않습니다.

## 웹 푸시 알림
- 계정 탭의 **알림 켜기**로 브라우저 푸시를 구독합니다. HTTPS(또는 localhost)에서만 동작합니다.
- 알림 대상: 친구 신청, 새 쪽지, **내 턴이 시작됐는데 탭이 백그라운드일 때**, 길드 주간 보상.
- 계정당 최대 5개 기기를 등록하며, 만료된 구독(404/410)은 전송 시 자동 정리됩니다.
- VAPID 키는 `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` 환경 변수를 우선 사용합니다. 없으면 서버가 1회 생성해 `push.json`(또는 PostgreSQL `kv_store`)에 보관합니다. 키를 바꾸면 기존 구독은 무효가 됩니다.
- `VAPID_SUBJECT`는 `mailto:` 또는 HTTPS URL이어야 하며, 미설정 시 `mailto:admin@kkeul.local`을 사용합니다.

## 길드 주간 대항전
- 길드 탭에서 이번 주 순위와 내 기여도를 볼 수 있습니다. 주차는 KST 월요일 시작 ISO 주차입니다.
- 랭크 1:1 승리: 기본 30점 + 연승 보너스(최대 20점). 4인 대회 우승: 60점.
- 가입 직후 점수 파밍을 막기 위해 **가입 24시간 뒤부터** 점수가 반영됩니다.
- 기여 상한: 1인당 하루 240점, 주 900점.
- 주가 끝나면 상위 3개 길드의 **이번 주에 점수를 낸 길드원**에게 1위 20,000 / 2위 10,000 / 3위 5,000코인을 지급합니다. 가입만 하고 기여하지 않은 길드원에게는 지급하지 않습니다. 지급은 `economy_ledger`의 `guildweek:{주차}:{길드}:{계정}` 멱등 키로 중복되지 않습니다.

## 길드 1:1 주간 대항전
- 같은 주에 점수를 낸 길드끼리 **점수가 가까운 순서로 1:1 매칭**되며, 매칭은 그 주 동안 고정됩니다.
- 길드 탭에서 상대 길드와 현재 점수, 통산 전적, 최근 결과를 확인할 수 있습니다.
- 주간 종료 시 점수가 높은 길드가 승리합니다. **이번 주에 기여한 길드원에게만** 승리 8,000 / 무승부 5,000 / 패배 3,000코인을 지급합니다.
- 보상은 `economy_ledger`의 `guildduel:{주차}:{길드}:{계정}` 멱등 키로 중복 지급되지 않으며, 기존 주간 리더보드 1~3위 보상과 별도로 지급됩니다.

## 닉네임 변경
- 계정 탭에서 이름을 저장/변경합니다. 첫 1회는 무료, 이후 1회당 **1,000,000코인**입니다.
- 성공하면 계정 탭에 **"✅ 현재 닉네임: … — 적용 완료 (시각)"** 배너가 남고, 상단 닉네임 칩·방 상태·순위표·단어장이 즉시 갱신됩니다.
- 서버는 `player:nameUpdated`에 `nickname`, `previousNickname`, `appliedAt`, `cost`, `money`를 함께 돌려줘 화면과 저장 결과가 어긋나지 않게 합니다.

## 단어장 동기화·복습 퀴즈
- 단어장은 계정(플레이어 데이터)에 최대 300개까지 저장되고, 접속 시 브라우저에 있던 단어가 자동으로 병합됩니다. 기기를 바꾸거나 브라우저 저장소를 지워도 유지됩니다.
- **복습 퀴즈**는 저장한 단어가 4개 이상일 때 시작할 수 있고, 초성 힌트와 4지선다로 최대 8문제를 냅니다.
- 서버 이벤트: `wordbook:list`, `wordbook:add`, `wordbook:remove`, `wordbook:merge`, `wordbook:clear`.

## 리플레이 공유
- 리플레이 모달의 **공유 링크**를 누르면 30일 동안 유효한 링크가 만들어져 클립보드에 복사됩니다.
- 링크는 `/?replay=<토큰>` 형태이고 토큰은 추측할 수 없는 12자입니다. 단어·닉네임·턴·깊이만 저장하며 내부 ID는 저장하지 않습니다.
- 서버에는 최대 500개까지 보관하고 오래된 것부터 정리합니다. 링크를 아는 사람은 로그인 없이 열람할 수 있습니다.

## 운영 지표
- `GET /api/metrics`에서 방 수, 접속자, 랭크/대회 대기열, DB 모드, 푸시 활성화, 클러스터 상태, 메모리를 확인합니다.
- `GET /api/replay/:token`은 공유 리플레이를 조회합니다. 두 응답 모두 캐시하지 않습니다.

## 계정 복구·기기 연결
계정 탭에서 **복구 코드**를 발급하면 닉네임과 코드로 새 기기에서 계정을 되찾을 수 있습니다. 코드 원문은 발급 직후 한 번만 표시되고 서버에는 해시만 저장됩니다. **기기 연결 코드**는 10분 동안 한 번만 사용할 수 있으며, 연결 시 새 기기의 게스트 데이터는 대체됩니다. 운영 환경에서는 `RECOVERY_PEPPER`를 비밀 환경 변수로 지정하세요. 값을 바꾸면 기존 복구 코드가 모두 무효가 됩니다.

## Render 배포
1. Build Command는 `npm install`, Start Command는 `npm start`로 설정합니다.
2. 웹 서비스 **Environment**에서 `DATABASE_URL`(Neon pooled connection string)과 `OPENDICT_API_KEY`(우리말샘 발급 키)를 각각 비밀 환경 변수로 설정합니다. API 키를 브라우저 코드나 Git에 넣지 마세요.
3. 저장 후 새 배포가 완료되면 `https://<서비스주소>/api/health`가 HTTP 200이고 `db`가 `"postgres"`인지 확인합니다.
4. `https://<서비스주소>/api/dictionary/definition?word=나무`를 호출해 HTTP 200과 `source: "우리말샘"`, 하나 이상의 `entries`가 반환되는지 확인합니다. `503`이면 API 키 환경 변수 저장과 새 배포 여부를 확인하세요.

## 데이터 저장 (초기화 방지)
서버는 플레이어·시즌·친구·관리자 설정·단어 신청·버그 제보 데이터를 저장합니다.
Render 등 **임시 파일 시스템** 환경에서는 기본 JSON 파일 저장 방식이 재배포/재시작 시 초기화되므로 아래 설정을 사용하세요.

- **`DATABASE_URL` 지정 시 (권장)**: 모든 데이터를 PostgreSQL `players` 테이블과 `kv_store` 테이블에 저장합니다. JSON 파일 저장과 자동 동기화됩니다.
- **`KK_DATA_DIR` 지정 시**: 설정한 디렉터리에 JSON 파일들을 보존합니다. (예: `/app/data`)
- 두 설정이 모두 없으면 기본 JSON 파일(`data/*.json`)에 저장하며, 안정성을 위해 `.bak` 파일이 자동 생성되고 원본 손상 시 복원됩니다.
- 단어·AI 목록 파일(`data/*.txt`)은 git에 포함되어 있어 초기화되지 않습니다.

### Render에서 PostgreSQL 연결하기 (무료)
1. Render 대시보드 → **New** → **PostgreSQL** → 무료 인스턴스 생성.
2. 생성된 DB의 **Internal Database URL**을 복사합니다.
3. Render 대시보드 → 본 **웹 서비스** → **Environment** → **DATABASE_URL**에 붙여넣고 저장(재배포 자동 진행).
4. 재배포 후 `https://<서비스주소>/api/health`를 열어 응답이 `"db":"postgres"`인지 확인합니다.
   - `"db":"json"`으로 나오면 환경변수가 안 들어갔거나 연결이 실패한 것이므로 Render 로그에서 `PostgreSQL 연결 실패` 오류를 확인하세요.
- 이전에 임시 파일 시스템에만 있던 데이터는 복구할 수 없지만, 연결 이후에는 재배포/재시작에도 돈·점수·시즌·친구 등이 유지됩니다.

### 다중 인스턴스 운영 (게임 코어 + 웹 릴레이)
방·턴 타이머·랭크/대회 대기열·접속자 상태는 **게임 코어 한 대**에만 둡니다. 나머지 인스턴스는 정적 파일을 직접 서빙하고 Socket.IO·상태성 API를 게임 코어로 프록시하는 **웹 릴레이**로 동작합니다. 이용자가 어느 웹 인스턴스에 접속해도 모든 실시간 요청이 같은 코어로 도착하므로 방 목록·매칭·관전 상태가 갈라지지 않습니다.

**구성**

| 역할 | 환경 변수 | 하는 일 |
|------|-----------|---------|
| 게임 코어 | `CLUSTER_ROLE=game` | 방/턴/대기열/접속자 상태, Socket.IO 엔진, 상태성 API |
| 웹 릴레이 | `CLUSTER_ROLE=web`<br>`CLUSTER_GAME_URL=https://게임코어주소` | 정적 파일, `/socket.io`·`/api` 프록시 |
| 단일 인스턴스 | 둘 다 비움 | 기존과 동일하게 한 프로세스가 모두 처리 |

- 게임 코어와 웹 릴레이는 같은 PostgreSQL `DATABASE_URL`을 사용해야 합니다.
- 게임 코어는 시작할 때 `cluster_leases`에 lease를 잡습니다. 같은 DB에서 두 번째 게임 코어가 뜨면 lease를 얻지 못하고 종료합니다. `cluster_nodes`에는 살아있는 인스턴스 heartbeat가 기록됩니다.
- Render처럼 새 인스턴스를 먼저 띄우는 배포에서는 새 인스턴스가 lease를 인계받습니다. 조건은 **같은 서비스**(`RENDER_SERVICE_ID`, 없으면 같은 공개 URL)이고 (a) `RENDER_GIT_COMMIT`이 기존 소유자와 다르거나, (b) 커밋을 비교할 수 없을 때(같은 커밋 재배포·커밋 정보 없음) 기존 소유자가 `CLUSTER_TAKEOVER_GRACE_MS`(기본 20000ms)보다 오래 전에 기동한 경우입니다. 인계 직후 이전 인스턴스는 다음 heartbeat에서 lease 상실을 감지하고 종료합니다. 같은 시점에 함께 뜬 인스턴스로 수를 늘리는 스케일아웃은 인계하지 않으므로, 게임 코어를 늘리지 말고 추가 인스턴스는 `CLUSTER_ROLE=web`으로 띄우세요.
- `/api/health`와 `/api/cluster/status`는 웹 릴레이에서도 로컬로 응답합니다. 나머지 `/api`는 기본적으로 게임 코어로 프록시합니다(`CLUSTER_PROXY_API=0`으로 끌 수 있음).
- Socket.IO는 게임 코어에만 붙으므로 **sticky session이 필요 없습니다.** 웹 릴레이는 HTTP 폴링과 WebSocket 업그레이드를 모두 프록시합니다. 게임 코어에는 30초 `connectionStateRecovery`가 켜져 있어 짧은 끊김 뒤 방 복구를 돕습니다.
- 웹 릴레이의 `CLUSTER_GAME_URL`은 게임 코어 자신의 주소여야 하며, 웹 릴레이 자신을 가리키면 순환으로 판정해 `508`을 반환합니다. Render에서는 게임 코어를 별도 서비스(또는 별도 인스턴스 URL)로 두고 웹 서비스에서 그 주소를 지정하세요.

**운영 확인**

```bash
curl -s https://<주소>/api/health | jq '.cluster'
curl -s https://<주소>/api/cluster/status | jq '{role, lease, nodes}'
```

게임 코어는 `role: "game"`, `lease: "acquired"`이고, 웹 릴레이는 `role: "web"`, `lease: "relay"`입니다. 웹 릴레이에서 `/socket.io/socket.io.js`와 WebSocket 핸드셰이크가 200/101로 통과하는지도 확인하세요.

**한계**

- 게임 CPU는 게임 코어 한 대에 모입니다. 웹/정적/연결 수는 늘릴 수 있지만 방 시뮬레이션 자체의 수평 확장은 다음 단계(방 단위 샤딩)입니다.
- 게임 코어가 재시작되면 메모리에 있던 진행 중 방·대기열은 사라집니다. 플레이어·코인·전적은 PostgreSQL에 남습니다. 무중단 방 복구가 필요하면 방 스냅샷과 타이머 복원을 추가해야 합니다.
- 코인 지급은 `economy_ledger`의 `UNIQUE(idem_key)`로 같은 보상 요청이 두 번 지급되지 않게 막지만, 플레이어 잔액 갱신 자체는 아직 계정 단위 직렬화가 아닙니다.

### 플레이어 데이터 삭제 (운영 도구)
`node tools/purge-player.js <닉네임>`은 삭제 대상을 보고만 하고, `--apply`를 붙이면 JSON 백업 후 players·전적·friends·시즌 등 관련 데이터를 정리합니다. TLS는 시스템 CA로 검증하며 URL의 `sslmode=no-verify`/`disable`은 무시합니다. 사설 CA를 쓰는 DB는 `DATABASE_CA_CERT`에 PEM 문자열이나 인증서 파일 경로를 지정하세요.
